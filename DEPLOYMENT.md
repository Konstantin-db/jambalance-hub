# Публикация Рабочей Станции

Исходный код сайта хранится в GitHub, а опубликованные файлы обслуживает хостинг REG.RU. Workflow `.github/workflows/deploy-reg-ru.yml` синхронизирует сайт с REG.RU по FTPS с проверкой сертификата.

## Однократная настройка

### 1. Создайте отдельный FTP-доступ для публикации

В ISPmanager откройте **FTP-пользователи → Создать** и создайте пользователя с именем `jamdeploy`. REG.RU добавит к нему префикс аккаунта, итоговый логин будет `u3551193_jamdeploy`.

В качестве домашней директории выберите корень сайта `/www/hub.jambalance.ru`. Это ограничит доступ пользователя файлами Рабочей Станции.

Сохраните или сгенерируйте пароль этого FTP-пользователя.

### 2. Сохраните пароль в GitHub

1. Откройте [секреты Actions репозитория](https://github.com/Konstantin-db/jambalance-hub/settings/secrets/actions).
2. Нажмите **New repository secret**.
3. Имя секрета: `REG_RU_FTP_PASSWORD`.
4. Значение: пароль FTP-пользователя `u3551193_jamdeploy`.

Не отправляйте пароль в чат и не добавляйте его в файлы репозитория.

### 3. Запустите первую публикацию

Откройте [Actions в репозитории](https://github.com/Konstantin-db/jambalance-hub/actions), выберите **Publish Workstation to REG.RU → Run workflow**, укажите ветку `main` и запустите публикацию. Дождитесь зелёного статуса.

После первой успешной публикации изменения сайта в `main` будут загружаться автоматически. Повторный запуск доступен в **Actions**.

## Что публикуется

В корень сайта загружаются файлы проекта; SQL-миграции из `supabase/` и файлы настройки GitHub не копируются. Workflow не очищает каталог целиком и сохраняет серверные `.htaccess` и `.well-known/`. При удалении файла из GitHub синхронизация удалит его предыдущую опубликованную копию с хостинга.

Автопубликация запускается при изменениях в `main`, кроме изменений только в `.github/`, `DEPLOYMENT.md` или `supabase/`. Для этих случаев доступен ручной запуск.
